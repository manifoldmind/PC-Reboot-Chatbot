# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ)
**Наименование проекта:** Чат-бот самообслуживания `PC-Reboot-Chatbot`  
**Версия документа:** 1.0

---

## 1. Цели и задачи
- **Цель:** Снизить нагрузку на службу поддержки 1-й линии за счет автоматизации рутинной операции перезагрузки ПК/виртуальных машин.
- **Задачи:**
  - Предоставить пользователю удобный интерфейс (в корпоративном мессенджере/веб-чате) для инициации перезагрузки.
  - Обеспечить интеграцию с CMDB для валидации прав пользователя на устройство.
  - Обеспечить интеграцию с Naumen для полного цикла управления инцидентом (создание → выполнение → закрытие).

---

## 2. Участники процесса
| Роль | Описание |
| :--- | :--- |
| **Пользователь** | Сотрудник компании, желающий перезагрузить закрепленное за ним устройство. |
| **Чат-бот** | Исполнительный механизм (Backend-сервис), обрабатывающий диалог и команды. |
| **CMDB** | Источник данных об активах (инвентарная система). |
| **Naumen (ITSM)** | Платформа для управления инцидентами и заявками. |
| **Target PC/VM** | Целевая операционная система (Windows/Linux), подлежащая перезагрузке. |

## 3. Функциональные требования (Сценарии работы)

### 3.1. Основной (счастливый) сценарий
| Шаг | Действие | Технические детали |
| :--- | :--- | :--- |
| **1** | Пользователь нажимает кнопку **"Перезагрузить мой ПК"** в интерфейсе бота. | Бот получает `user_id` из контекста диалога. |
| **2** | Бот отправляет запрос в CMDB. | Запрос по `user_id` (или `employee_number`) для получения списка активных КЕ (компьютерных единиц). Фильтр: статус "В эксплуатации". |
| **3** | Бот выводит список устройств интерактивными кнопками. | Формат кнопки: `{Hostname}`. Если КЕ одна — бот сразу предлагает перезагрузить её (пропуская шаг выбора). Если КЕ нет — уведомляет пользователя и предлагает создать заявку вручную. |
| **4** | Пользователь выбирает конкретный ПК из списка. | Нажатие на кнопку триггерит `callback` с `device_id`. |
| **5** | Бот формирует заявку в Naumen. | **Метод:** `createIncident`. <br> **Поля:** Краткое описание, Категория (Инцидент/Запрос), Приоритет (Низкий), Ответственный (автоматически назначается на бота/сервисный аккаунт). <br> **Статус:** "В работе". |
| **6** | Бот инициирует удаленную перезагрузку выбранного ПК. | Вызов протокола удаленного управления (WinRM/SSH). **Таймаут операции:** 60 секунд. |
| **7** | Бот ожидает подтверждение выполнения (или ошибку). | После отправки команды reboot, бот ждет 30 секунд и проверяет доступность ПК по ICMP/Ping (чтобы убедиться, что он ушел в перезагрузку). Подробная проверка доступности после ребута не требуется на этом этапе. |
| **8** | Бот отправляет пользователю сообщение об успехе. | Текст: *"Устройство [Hostname] успешно перезагружено. Ожидайте загрузку в течение 2-3 минут."* |
| **9** | Бот закрывает заявку в Naumen. | **Метод:** `closeTicket`. <br> **Статус:** "Решено". <br> **Комментарий:** "Перезагрузка выполнена успешно по запросу пользователя." |

---

### 3.2. Альтернативные сценарии (Обработка ошибок)

| Ситуация | Действие бота |
| :--- | :--- |
| **В CMDB нет устройств за пользователем** | Бот уведомляет: *"В базе не найдено закрепленных ПК. Обратитесь в поддержку лично."* Заявка не создается. |
| **Naumen недоступен (таймаут/500 ошибка)** | Бот сообщает пользователю о технических проблемах. Логирует ошибку. Перезагрузка НЕ выполняется (блокирующая ошибка). |
| **ПК не отвечает на команду перезагрузки (недоступен по сети)** | Бот создает заявку в Naumen (чтобы зафиксировать инцидент), но оставляет её в статусе "В работе" с комментарием: *"Устройство недоступно. Проверка связи не удалась."* Пользователю отправляется сообщение: *"Не удалось связаться с ПК. Заявка [№] передана инженеру."* |
| **ОС ПК отказала в выполнении команды (Access Denied)** | Бот закрывает заявку с комментарием: *"Ошибка доступа, проверьте учетные данные сервисного аккаунта."* Уведомляет пользователя об ошибке. |
| **Пользователь закрыл чат или не выбирает ПК (таймаут)** | Если пользователь не нажал кнопку в течение 5 минут, бот завершает диалог командой *"Время сессии истекло. Начните заново."* Заявка не создается. |

## 4. Требования к интеграциям (API)

### 4.1. Интеграция с CMDB
- **Протокол:** REST API (JSON).
- **Эндпоинт:** `GET /api/assets/by_user?user_id={id}`
- **Входные данные:** `user_id` (String).
- **Выходные данные (массив):**
  ```json
  [
    {
      "asset_id": "PC-001",
      "hostname": "WS-K534D",
      "ip_address": "192.168.1.45",
      "type": "Physical_PC" | "VM",
      "os": "Windows 10 Pro" | "Linux"
    }
  ]
  ```

### 4.2. Интеграция с Naumen (ITSM)
- **Протокол:** SOAP / REST API (уточнить версию вашей системы).
- **Создание заявки:** Метод `createTicket`. Поля: `title`, `description`, `assignee_group`, `urgency`.
- **Обновление/Закрытие:** Метод `updateTicket`. Поля: `status`, `resolution_note`.

### 4.3. Удаленное управление ПК
- **Для Windows:** WinRM (порт 5985/5986) или WMI (135). Использовать сервисный аккаунт домена.
- **Для Linux:** SSH (порт 22) с ключами.
- **Команды:**
  - Windows: `shutdown /r /t 5 /f` (перезагрузка через 5 сек с форсированием).
  - Linux: `sudo reboot`.

## 5. Нефункциональные требования

| Параметр | Требование |
| :--- | :--- |
| **Язык реализации** | Python 3.10+ (рекомендуется) / Node.js / Go (на усмотрение команды). |
| **Стек бота** | Telegram Bot API / Slack Bolt / Корпоративный мессенджер (уточнить). |
| **Производительность** | Время ответа на действие пользователя не более 2 секунд (без учета времени выполнения reboot). |
| **Логирование** | Все шаги (запросы в CMDB, Naumen, команды перезагрузки) должны писаться в структурированный лог (JSON) с уровнем INFO/ERROR. |
| **Безопасность** | <ul><li>Аутентификация пользователя в боте через корпоративный SSO (OAuth2/OpenID).</li><li>Строгая проверка принадлежности ПК пользователю из CMDB (чтобы нельзя было перезагрузить чужой ПК, даже зная ID).</li><li>Секреты (токены API, пароли сервисных аккаунтов) хранить в зашифрованном `.env` или Vault.</li></ul> |
| **Надежность** | Автоматический ретрай (повтор) запроса к Naumen и CMDB до 3 раз при сетевых сбоях с экспоненциальной задержкой. |

## 6. Требования к интерфейсу пользователя (UI/UX)

1. **Кнопки:** Использовать `Inline Keyboard Buttons` (чтобы исключить ручной ввод текста от пользователя, снижая риск ошибок).
2. **Текст сообщений:**
   - *Приветствие:* "Привет! Нажмите кнопку ниже, чтобы перезагрузить ваш компьютер."
   - *Выбор ПК:* "Мы нашли несколько устройств. Выберите то, которое нужно перезагрузить:"
   - *Прогресс:* "Выполняю перезагрузку... (Это займет до 1 минуты)."
3. **Мультиязычность:** На начальном этапе — только русский язык (в коде заложить возможность добавления локализации через `.i18n` файлы).

## 8. Критерии приемки (Definition of Done)
- [ ] Пользователь может запустить сценарий по кнопке.
- [ ] Бот корректно отображает список ПК из CMDB (или пишет, что их нет).
- [ ] При выборе ПК в Naumen создается заявка с корректным заполнением.
- [ ] ПК реально перезагружается (проверяем по логам ОС целевой машины).
- [ ] Заявка автоматически закрывается после успешной перезагрузки.
- [ ] Все ошибки (отказ сети, недоступность ПК) обрабатываются без падения бота и с понятным сообщением пользователю.
- [ ] Логи содержат ID заявки Naumen для каждого сеанса.
